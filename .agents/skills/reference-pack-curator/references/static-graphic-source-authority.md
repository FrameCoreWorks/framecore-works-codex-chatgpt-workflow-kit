# Static Graphic Source Authority

Extend the existing Reference Pack with per-property ownership. One source can
govern several properties, but its position in a list never grants blanket
authority. Record current-request alias, real source, availability, required
status, roles, protected properties, allowed changes and conflicts.

| Role | Typical protected properties | Never inferred from this role |
| --- | --- | --- |
| Identity | Likeness, apparent age, facial geometry, approved body/hair traits | Identity from a style reference |
| Product / garment | Silhouette, construction, closures, counts, seams, label boundary | New features or invented unseen geometry |
| Packaging / logo | Mark spelling, shape, layout, panel edges, color intent | Certification or an official master from a generated approximation |
| Composition | Arrangement, scale, viewpoint within approved limits | Override of exact copy or product construction |
| Style / material / light | Permitted palette, rhythm, surface or lighting behavior | Transfer of source people, wording, clothing or affiliation |
| Edit source | Actual current approved image and preserve set | A new composition or recovery of invisible original layers |

Product truth, selected wording and identity locks outrank stylistic
convenience for those properties. Equally authoritative sources disagreeing on
a required property need a decision before finalization. Missing required
images stay unavailable; do not synthesize authority from prose.

For example, `product_front` may lock a cylindrical bottle, one cap and one
continuous label boundary. `lighting_ref` controls side light only. Splitting
the label into strips to match the second image violates the first source.
Topology and counts are more useful than repeating "exact" in a prompt.

For strict preservation, attach the governing source to the actual generation
or edit request. A named alias in a document is not an attachment. Observe host
reference limits and controls rather than assuming API features exist natively.
No seed, weight, mask or repeated phrase guarantees identity or geometry.

Source approval and factual verification are separate. A supplied price, logo
or claim records its authority without proving independent verification. Keep
uncertainty explicit. For a requested source-poster rebuild, transcribe required
strings and preserve facts while changing only permitted design properties.

Hand off these records through `reference_authority_fit`; direction and
prompting reuse them, while QA compares actual pixels against the sources.
