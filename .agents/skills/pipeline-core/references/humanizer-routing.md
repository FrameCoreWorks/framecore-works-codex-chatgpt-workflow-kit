# Humanizer Routing

Use `humanizer` when copy needs to sound natural, specific, audience-aware, and
less generic while remaining truthful and owned by the user or approved author.

Common routes:

- `copy-voice` for Copy Pack ownership, VO, social copy, dialogue, taglines,
  CTA work when explicitly needed, and ready-to-use editorial delivery
- `delivery-documentation` for final user-facing summaries
- `brief-architect` when messy input needs clearer phrasing without changing facts
- `caption-studio` when approved wording needs timing, subtitle, or screen-space
  treatment rather than silent rewriting

Humanizer must preserve factual claims, exact required copy, legal wording, and
user-approved terminology. It must not invent personal experience, testimonials,
sources, quotes, metrics, results, promises, or user history. It does not
imitate a living person's distinctive style or optimize text to evade detectors.

For ready-to-use text, `copy-voice` records `author_context`,
`fact_and_lock_ledger`, `human_voice_review`, and `copy_delivery_loop` in the
Copy Pack. The existing Loop Protocol supplies the bounded sequence:

`draft -> deep review -> revision -> final QA -> delivery`

Default to ordinary, useful writing. A hook, CTA, list, heading, emoji,
hashtag, question, or lightly rough voice is conditional on author, audience,
channel, goal, exact-copy, legal, timing, or accessibility needs. Controlled
imperfection is off by default and is never allowed in precision-critical text.

See `human-voice-and-copy-delivery.md` for the complete policy.
