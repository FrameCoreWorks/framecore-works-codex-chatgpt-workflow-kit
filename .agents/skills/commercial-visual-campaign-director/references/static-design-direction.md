# Static Graphic Direction

This is domain knowledge for the existing `static-direction` responsibility.
It uses the same Static Direction Contract, `direction_fit` gate and handoffs.
It does not create another skill, orchestrator or execution route.

## Match the requested scope

- Advice or layout critique: answer that question directly.
- Concepts only: develop mechanisms and stop with assessable options.
- Copy only: use `copy-voice`; no prompt or rendering intake.
- A ready direction or narrow edit: preserve it; skip a new brainstorm.
- A complete graphic: prepare only the missing direction, copy, reference and
  prompt decisions, then hand off for user-requested native execution.
- Repository discussion or installation: do not start graphic production.

Preserve decisions already supplied or approved. Ask only when a missing answer
changes the concept, exact text, source truth, intended deliverable or authority.
Ordinary reversible composition choices need no additional approval.

## Communication before styling

Resolve objective, audience response, reading mode (`glance`, `brief_scan` or
`deliberate_read`), information burden, visual thesis, composition, attention
order, type/image relation, then visual language and material treatment.
A word, a datum, negative space or a relation can be the dominant event.
One-word work does not require a hero image, CTA or three attention levels.

For open mechanisms, use [concept development](concept-development-and-originality.md).
Develop paired concept/copy routes with `copy-voice`; do not independently mix
unrelated style and slogan menus. Different palettes are variants, not different
concepts. If concept and copy are already approved, carry them forward.

Record a Core Concept Lock: premise, mechanism, distinctive hook, allowed
adaptations and forbidden substitutions. Source constraints and exact copy
remain separate locks. A feasibility problem must not silently replace them.

- [Composition atlas](poster-style-and-composition-atlas.md): attention,

- [Movements and production](poster-movements-and-production-atlas.md):
  historical context and material-process logic when material to the brief.
- [Optional poster codes](event-poster-code-workflow.md): exact catalog lookup
  or interpreted directions when useful; ordinary briefs need no codes.

The atlases use `strategy`, `concept.lock`, `copy.items` and `feasibility` as
planning notation. Carry these meanings in the existing direction contract,
Copy Pack, reference pack and prompt constraints. They do not introduce a new
global schema, runtime state machine or mandatory user-facing questionnaire.

## Handoff and stop

Include the selected concept and allowed changes, reading mode, attention
order, composition mechanism, required text IDs, reference property locks,
format variants and `production_intent` in the existing Static Direction
Contract. Distinguish `concept_raster`, `digital_final` and `production_master`.
The latter requires a DTP/layout handoff; a generated raster cannot establish
editable type, a dieline, functional barcode or prepress compliance.

Copy authority is per item; user-approved wording is not independently verified
claim evidence. Keep unselected alternatives out of prompt handoffs. Required
metadata stays required even when visually secondary.

`image-prompting` owns prompt compilation and typography feasibility;
`reference-curator` resolves property authority; `qa-iteration` inspects actual
outputs. Separate components are planning under `asset-manifest` only when
explicitly requested. The ordinary graphic remains one integrated output.

Stop at the requested direction, concepts or handoff. A reference read or catalog
selection never authorizes generation, file modification or external upload.
