# Static Graphic Review

Use the existing `post_execution_fit` gate and QA / Iteration Report. Inspect
the actual candidate and governing references at intended use size and full
resolution. A prompt, generated-state label, catalog code or attractive preview
does not establish an accepted image.

| Check | Required observation | Failure route |
| --- | --- | --- |
| Concept | Selected mechanism and its text/image relationship survive | `static-direction` if strategy failed |
| Hierarchy | Intended attention order and useful scan path survive | Layout repair; do not force three levels |
| Exact copy | All selected strings, punctuation, diacritics, dates, prices and required metadata; no extras | One wrong required string fails; protect correct strings |
| Legibility | Required text readable at intended use size, with clear spacing, local contrast and intact margins | Scoped repair or DTP for fixed infeasible constraints |
| References | Protected identity, apparent age, product, garment, logo and label topology | Identify changed property; do not average fidelity failures |
| Materials | Intended local surface and process logic; no unwanted repetition or smoothing | Use material diagnosis, preserve intentional detail |
| Additions | No invented claims, partners, facts, marks, mockup or unrequested variants | Remove unsupported additions |
| Delivery | Actual file dimensions/format/alpha and requested output properties | Unknown is not verified; raster is not a production master |

Record `pass`, `fail`, `Unknown` or justified `not_applicable` per check, with
observed evidence and inspected file/version. Any failed or unknown critical
check blocks acceptance. Optional aesthetic preferences do not require another
render. OCR can support exact-text checks but cannot replace visual inspection.
Do not claim contrast certification, font identity or prepress readiness
without the relevant measurements and source evidence.

Read [material diagnosis](material-artifact-diagnosis.md) for observed repeating
cells, halos, tiling or over-smoothing. Judge unwanted artifact, retained
detail and creative intent separately. Preserve intentional halftone/pixel
patterns; correcting bark must not smooth faces, fabrics or unrelated surfaces.

## Repair and stop

- Accept only when required checks pass and the requested result is met.
- For a local defect, create a scoped correction packet: actual current image,
  one permitted change, changed/protected text IDs, preserve set and regression
  checks. An exact replacement already requested by the user needs no new copy
  discovery. Check the changed region and all protected properties afterward.
- For a failed mechanism, loop back to direction. Do not fix strategy by adding
  an ever-longer exclusion list to a bad prompt.
- For exact editable typography, functional codes, dielines or print masters,
  return `dtp_required` with the bounded layout handoff.
- If generation failed or inspection is unavailable, report that state. A
  proposed repair is not another tool call or permission for an external route.

Keep the last approved base when a candidate fails; compare serial edits with
that base to detect cumulative drift. A filename or the newest version is not
acceptance evidence. Deliver only the existing QA allowlist and stop under the
same Loop Protocol when sufficient.

For explicitly requested component sets, separate per-file inspection, user
selection and assembled-design QA. Verify actual alpha, not a painted
checkerboard, and inspect edges on light and dark backgrounds. Replacing a
subject may require rechecking its shadow without changing an approved
background. Packaging selected files cannot certify an uninspected assembly.
